# NexTarget-server v0.3.0 — 2026-09-02

Release NT-071 (Postgres Neon + Alembic) et items en attente depuis v0.2.0
(NT-049, landing page, en-têtes de sécurité navigateur).

## Plateforme & Déploiement

- **NT-071** — Migration SQLite → PostgreSQL Neon avec Alembic.
  - Alembic devient la **source de vérité du schéma de production**
    (`alembic/versions/` — migration initiale `user` + `refreshtoken`).
    `SQLModel.metadata.create_all()` ne s'exécute plus qu'en SQLite (dev/tests).
  - Deux connexions distinctes : `DATABASE_URL` (poolée, rôle applicatif à
    privilèges minimaux) pour le runtime ; `DATABASE_MIGRATION_URL` (directe,
    rôle propriétaire) pour Alembic et `pg_dump`.
  - Migrations exécutées avant Uvicorn (`scripts/run_migrations.py`, appelé
    par `start.py`) : un échec bloque le démarrage sans exposer de secret
    (seul le type d'exception est journalisé).
  - Driver PostgreSQL explicitement déclaré (`postgresql+psycopg2`).
  - Bascule prévue sur une base Neon **vide** (aucun import des données
    SQLite) ; reconnexion des utilisateurs requise une seule fois.
  - Procédure complète (création Neon, bascule, sauvegarde `pg_dump`,
    restauration, rollback) : [`docs/tech/postgres_neon_migration.md`](../tech/postgres_neon_migration.md).

## Auth & Compte

- **NT-049** — Page d'administration read-only des utilisateurs
  (`GET /app/admin/users`), protégée par HTTP Basic sur HTTPS et une
  empreinte scrypt salée (`ADMIN_PASSWORD_HASH`) ; aucune donnée sensible
  exposée, aucune mutation possible.

## Plateforme & Contenu public

- Page d'accueil publique et statique sur `GET /` (métadonnées SEO,
  `robots.txt`, sitemap minimal).
- En-têtes de sécurité navigateur : CSP stricte sur la landing, HSTS en
  production, `nosniff`, Referrer-Policy, Permissions-Policy, protection
  anti-iframe.

## Compatibilité & déploiement

- **Aucun breaking change d'API.**
- **Nouvelles variables d'environnement, à saisir manuellement dans Render**
  (`sync: false`, jamais commitées) — voir
  [`docs/tech/render_setup.md`](../tech/render_setup.md) et
  [`docs/tech/postgres_neon_migration.md`](../tech/postgres_neon_migration.md) :
  - `DATABASE_URL` — connexion poolée Neon du rôle applicatif `nextarget_app`.
  - `DATABASE_MIGRATION_URL` — connexion directe Neon du rôle propriétaire
    `neondb_owner`.
- ⚠️ **Prérequis avant bascule prod** : créer le projet Neon `nextarget-prod`
  (Frankfurt) et le rôle `nextarget_app` à privilèges minimaux **avant** de
  renseigner les variables ci-dessus dans Render. Tant qu'elles ne sont pas
  renseignées, le service continue de fonctionner sur la configuration
  précédente (aucune régression au moment du merge).
- ⚠️ **Après bascule** : tous les utilisateurs doivent se reconnecter une
  fois (nouvelle base vide) ; leur couple `(email, provider)` recrée un
  compte identique côté Neon, sans doublon.
- SQLite reste le défaut en développement local et pour les tests unitaires.

Tests : 87 tests, dont 3 dédiés à PostgreSQL (`tests/test_migrations_postgres.py`,
exécutés uniquement si `NEXTARGET_TEST_POSTGRES_URL` est définie — skip
automatique sinon). Détail : `CHANGELOG.md`.
